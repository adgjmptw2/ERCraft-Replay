# 실용적인 교전 분석을 위한 작업 기준

## 우선순위

모든 개인 교전의 피해량과 지원 스킬의 시도·적중을 볼 수 있는 수준을 먼저 완성합니다. BIN 자료와 DAK 분석 화면을 비교 자료로 사용하되, 다른 도구와의 숫자 일치만을 정답으로 삼지는 않습니다. 작은 오차는 허용하고 그 크기와 발생 조건을 기록합니다.

1. 교전 누락·중복, 잘못된 플레이어 귀속, 큰 피해량 차이를 우선 수정합니다.
2. 교전별 추정 피해·교전 밖 피해·기록된 종료 통계를 함께 확인합니다. 일부 피해량이 미확정이어도 해당 교전을 숨기지 않습니다.
3. 지원 스킬의 시도·적중·적중률과 계산 불가 사유를 표시합니다. 누락된 증거를 빗나감이나 0으로 처리하지 않습니다.
4. 실제 사용할 수 있는 범위와 오차를 정리한 뒤 수집·계산 속도와 저장 구조를 개선합니다.

## 필요한 만큼 검증하기

기존 경기 자료를 기본 회귀 자료로 재사용합니다. 현재 공통 집계 검사는 서로 다른 연구 프로필의 9경기를 대상으로 했으며, 한 가지 고정 규칙의 독립 검증 표본으로 취급하지 않습니다. 피해 총계의 상대 오차 분포와 최대 차이, 교전 누락 수, 스킬 시도·적중 차이를 한 번에 비교합니다. 평균만으로 큰 오류를 숨기지 않으며, 실제 분포를 확인한 뒤 허용 범위를 결정합니다. 현재 문서는 오차율이 이미 기준을 통과했다는 선언이 아닙니다.

새 규칙은 표본 전체 비교와 해당 오류를 재현하는 집중 테스트로 검증합니다. 같은 입력의 반복 확인은 새 실패나 구현 변경이 있을 때만 진행합니다. 소수 사건의 미세한 차이를 추적하는 네이티브 분석은 다수 교전의 결과를 바꾸거나 큰 오류를 해결할 근거가 있을 때로 제한합니다. Opus 검토는 주요 변경 묶음에 적용합니다.

## 성능과 데이터 보관

품질 작업 중에는 신규 다운로드와 성능 실험을 보류합니다. 성능 작업을 재개하면 새 프로세스 시작과 다운로드를 포함한 결과 준비 시간을 측정합니다. 반복 실행과 서로 다른 경기에서 30초 이내인지 확인하며, 내부 계산 시간만으로 통과를 판정하지 않습니다.

분석용 보관소는 다음 세 층으로 나눌 계획입니다.

- 최소 회귀 자료: 대표 경기와 버전·스키마·GameDB 식별 정보.
- 재사용 분석 자료: 경기 원본 해시와 계산 버전으로 식별한 정규화 사건·교전·스킬 결과. 필요한 컬럼만 보관하고 압축·중복 제거를 적용합니다.
- 일회성 작업 자료: 다운로드·해독 중간 파일과 실패한 실험 산출물. 완료 후 제거하고 영구 보관소로 취급하지 않습니다.

개인 식별 자료는 공개 산출물과 분리합니다. 원본의 장기 보관 여부는 기존 데이터 정책을 따릅니다. 보관소 구현은 아직 완료되지 않았습니다.


테스트 자료는 저장 예산을 정해 관리하고, 재생성 가능한 중간 파일은 완료 후 정리합니다. 원본·소스·실행 의존성과 필요한 검증 근거는 보존합니다.
