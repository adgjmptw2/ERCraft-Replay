# 실용적인 교전 분석을 위한 작업 기준

## 우선순위

모든 개인 교전의 피해량과 지원 스킬의 시도·적중을 볼 수 있는 수준을 먼저 완성합니다. BIN 자료와 DAK 분석 화면을 비교 자료로 사용하되, 다른 도구와의 숫자 일치만을 정답으로 삼지는 않습니다. 작은 오차는 허용하고 그 크기와 발생 조건을 기록합니다.

1. 교전 누락·중복, 잘못된 플레이어 귀속, 큰 피해량 차이를 우선 수정합니다.
2. 교전별 추정 피해·교전 밖 피해·기록된 종료 통계를 함께 확인합니다. 일부 피해량이 미확정이어도 해당 교전을 숨기지 않습니다.
3. 지원 스킬의 시도·적중·적중률과 계산 불가 사유를 표시합니다. 누락된 증거를 빗나감이나 0으로 처리하지 않습니다.
4. 실제 사용할 수 있는 범위와 오차를 정리한 뒤 수집·계산 속도와 저장 구조를 개선합니다.

## 필요한 만큼 검증하기

기존 경기 자료와 검증 결과를 재사용하고, 빠진 실험체가 포함된 경기만 추가합니다. 기존 9경기와 새 8경기로 90종 모두의 실제 결과를 확인했습니다. 같은 75종 전체를 반복 처리하지 않습니다. 새 경기도 누락 실험체를 기준으로 선정했으므로 무작위 정확도 표본으로 취급하지 않습니다. 피해 총계의 상대 오차 분포와 최대 차이, 교전 누락 수, 스킬 시도·적중 차이를 한 번에 비교합니다. 평균만으로 큰 오류를 숨기지 않으며, 실제 분포를 확인한 뒤 허용 범위를 결정합니다. 현재 문서는 오차율이 이미 기준을 통과했다는 선언이 아닙니다.

새 규칙은 표본 전체 비교와 해당 오류를 재현하는 집중 테스트로 검증합니다. 같은 입력의 반복 확인은 새 실패나 구현 변경이 있을 때만 진행합니다. 소수 사건의 미세한 차이를 추적하는 네이티브 분석은 다수 교전의 결과를 바꾸거나 큰 오류를 해결할 근거가 있을 때로 제한합니다. Opus 검토는 주요 변경 묶음에 적용합니다.

## 성능과 데이터 보관

전체 캐릭터를 대상으로 실사용 가능한 품질을 확보하고 여러 경기로 확인한 뒤 처리 속도를 개선합니다. 성능 실험은 그 이후에 진행합니다. 성능 작업을 재개하면 새 프로세스 시작과 다운로드를 포함한 결과 준비 시간을 측정합니다. 반복 실행과 서로 다른 경기에서 30초 이내인지 확인하며, 내부 계산 시간만으로 통과를 판정하지 않습니다.

분석용 보관소는 다음 세 층으로 나눌 계획입니다.

- 최소 회귀 자료: 대표 경기와 버전·스키마·GameDB 식별 정보.
- 재사용 분석 자료: 경기 원본 해시와 계산 버전으로 식별한 정규화 사건·교전·스킬 결과. 필요한 컬럼만 보관하고 압축·중복 제거를 적용합니다.
- 일회성 작업 자료: 다운로드·해독 중간 파일과 실패한 실험 산출물. 완료 후 제거하고 영구 보관소로 취급하지 않습니다.

개인 식별 자료는 공개 산출물과 분리합니다. 원본의 장기 보관 여부는 기존 데이터 정책을 따릅니다. 현재 로컬 연구 구현은 경기별 SQLite와 원본·분석 식별 정보를 확인하는 참조 목록까지 연결했습니다. 전체 보관 정책과 일반 운영 적용은 아직 완료되지 않았습니다.


여러 경기 테스트는 한 번에 한 경기씩 처리합니다. 기존 입력을 재사용하는 품질 검사에서는 메모리에서 계산하고 작은 비교 보고서만 남깁니다. 경기마다 HTML·DB·중간 산출물을 복제하지 않습니다. 테스트 자료는 저장 예산을 정해 관리하고, 재생성 가능한 중간 파일은 완료 후 정리합니다. 원본·소스·실행 의존성과 필요한 검증 근거는 보존합니다.

## 현재 이어갈 작업

전체 요청 목록은 공통 수집 경로에 연결했고, 17경기에서 90종 모두의 피해량과 숫자 스킬 지표를 확인했습니다. 전체가 미확정이던 4개 지표는 계산을 복원했습니다. 남은 품질 작업은 일부 사용의 미확정과 피해 차이가 큰 3개 결과를 대상으로 하며 공통 원인이 있을 때 우선 수정합니다. 모든 개별 스킬의 완벽한 증명을 목표로 검사를 확대하지 않습니다. 미확정 사용이 있는 지표에는 조건부 적중률 범위를 표시하되 이를 검증된 오차범위로 부르지 않습니다. 특정 캐릭터의 세부 증명이나 같은 경기의 반복 재생성이 다음 작업의 기본값이 되지 않도록 합니다. 최신 집계와 한계는 [진행 현황](PROGRESS-20260926.md)을 기준으로 확인합니다.
