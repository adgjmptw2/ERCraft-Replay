# 구성과 데이터 흐름

## 저장소 구성

| 경로 | 역할 |
| --- | --- |
| `core/decoder/` | 바이너리 해석, 이벤트 추출, 계산, 공개 결과 변환과 검증 |
| `core/schema/` | 버전별 스키마, gameDb 해시 계약, 계산 실행 계획 |
| `core/data/` | 계산 규칙, 정적 이미지 및 출처 메타데이터 |
| `core/deliverables/` | 일부 스킬 계산 규칙의 정적 근거 |
| `worker/` | 기존 Windows 서비스의 큐·수집·분석·보존 연동 소스 |
| `viewer/` | 정적 웹 뷰어 소스 |
| `tools/` | 공개 파일 목록과 해시, 문법을 확인하는 로컬 검사 |

## 분석 흐름

1. 수집 계층에서 인증을 처리하고 리플레이를 임시 작업 영역에 받는다.
2. 리플레이 헤더의 버전과 gameDb 해시를 확인한다. 승인된 정확한 입력이 없으면 실패 상태를 보존한다.
3. Brotli payload와 MemoryPack 구조를 해석해 위치, 상태, 이벤트를 추출한다.
4. 분석 코어가 스킬 시도와 적중, 교전 관련 지표를 계산한다.
5. 공개 출력 변환기와 검증기를 거친 결과만 뷰어에 전달한다.
6. 워커가 준비 상태를 게시하고 임시 원본과 작업 중간 자료를 정리한다.

이 흐름은 서비스 구성의 설명이다. 공개 저장소에는 인증 설정, 경기 입력, 전체 계산 근거와 서비스 설치 구성이 들어 있지 않다.

## 계산과 화면의 경계

- 지표의 분모·분자와 이벤트 귀속은 코어에서 결정한다.
- 합산 적중률은 합산 적중 수를 합산 시도 수로 나눈 값이다.
- 뷰어는 계산된 결과의 재생, 플레이어 선택, 표시와 탐색을 담당한다.
- `null`, `unknown`, `unavailable`, `unresolved`는 미확인 상태다. 임의로 0이나 성공으로 바꾸지 않는다.
- 관측된 이벤트, 계산 결과, 개발 단계의 추정은 구분한다. 등록된 계산 규칙이 있다는 이유만으로 검증 완료로 표시하지 않는다.

## 버전 경계


코어 파일에는 해시 검증에 참여하는 코드와 JSON이 있다. 줄바꿈만 바꿔도 검증 결과가 달라질 수 있어 원본 바이트를 보존한다.
